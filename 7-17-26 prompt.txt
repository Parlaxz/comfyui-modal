# What went wrong in the previous commit

Treat the following findings as confirmed. Do not ask Explorer to rediscover them.

## 1. V2 is still a wrapper over the legacy remote runtime

`comfymodal_runtime.modal_transport.ModalTransport` falls back to:

```python
from modal_client import run_prompt_stream
```

It converts the typed plan back into legacy dictionaries and invokes the old `comfyapp.py` runtime.

The new `modal_app.py` is not a functioning Modal deployment:

* No complete production image.
* No real custom-node source inclusion.
* No class mounts.
* No GPU class registration.
* No `@app.cls`.
* No `@modal.method`.
* No real executor runner.
* No real preload integration.

Fix this by wiring a real shadow v2 Modal class and invoking it directly.

## 2. Restore state is duplicated and the new state is local-only

`execute_plan()` currently:

1. Calls the legacy `prepare_active_next_profile()`.
2. Publishes a new `RestorePlan`.
3. Writes that new plan into local `.runtime_state/`.
4. Sends the request through the old remote runtime, which reads the legacy active profile.

The new RestorePlan is therefore not consumed remotely.

Fix this by:

* Publishing the RestorePlan through an actual Modal remote method.
* Writing it to the actual runtime-state Modal Volume.
* Committing that Volume synchronously before GPU submission.
* Reading the exact same plan during the real v2 `snap=False` restore.
* Removing the duplicate legacy profile call from the v2 path once parity is proven.

## 3. Typed options discard live runtime and output settings

The typed options parser currently drops unknown fields instead of preserving them.

The live legacy runtime uses fields including:

* `quality`
* `webp_lossless_compression`
* `return_comparison_a`
* `runtime.cold_unet_early_load`
* Loader/preload settings.
* Additional production/output flags.

Until every field is explicitly typed, preserve all unknown legacy keys in a passthrough mapping.

V2 must not silently change:

* Output format.
* Output quality.
* Image Comparer A/B behavior.
* Compression.
* Runtime preload settings.
* Cancellation/progress behavior.

## 4. Trace merging destroys remote events

Current v2 code replaces:

```python
remote_trace["events"]
```

with local events.

Fix it so local and remote events are:

* Normalized.
* Combined.
* Deduplicated.
* Sorted by wall time for display.
* Kept identifiable by process.
* Never overwritten.

## 5. The new output collector does not match the live registry

The live production registry returns:

```text
node_id → list[entry]
```

The new `DirectOutputSink` tests use:

```text
node_id → output_key → list[entry]
```

Adapt the new output strategy to the real registry contract. Do not change the live registry merely to satisfy the new abstraction unless there is a strong demonstrated reason.

Missing output must be a hard execution failure for production runs. Do not report success and continue after materialization or collection fails.

## 6. Playground was partially cut over without the runtime switch

The default direct Playground path now enters `PlaygroundService` regardless of `COMFYMODAL_RUNTIME`, while Direct ComfyUI defaults to legacy.

Gate Playground with the same runtime switch as Direct:

```text
legacy → existing path
v2 → new execution service
shadow → build/compare plans without a second paid generation
```

Direct and Playground must call the exact same `execute_plan()` implementation.

## 7. The preload coordinator is disconnected

`ModelPreloadCoordinator` currently uses injected dummy callbacks and is not connected to:

* The real `snap=False` restore.
* Actual UNET loading code.
* Actual CLIP loading code.
* Actual CLIP prefill.
* Actual ComfyUI loader nodes.
* The real graph demand boundaries.

Port the proven legacy loader code into it and connect the complete lifecycle.

## 8. Deployment and runtime state are still legacy

The new deployment and state modules are mostly standalone test objects.

They do not yet replace:

* Real image construction.
* Real source inclusion.
* Real Modal deployment.
* Real Volume mounting.
* Real source identity.
* Legacy label-keyed runtime-config commits.
* Deployment mutation behavior.
* Deployment validation state.

For this pass, implement only enough deployment wiring to deploy and run the shadow v2 runtime correctly. Do not attempt unrelated deployment UI cleanup until the vertical slice works.
