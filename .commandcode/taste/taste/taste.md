# Taste
- Prefers analysis/forensics batches to be strictly local and read-only: no remote/paid work, no deploys or remote runs, no commits, no branches or worktrees, no subagents, and no runtime/optimization changes — the deliverable is a report, not code. Confidence: 0.9
- Insists timing analysis never mixes clock domains: every event must be mapped to one clock (preferring remote monotonic), and events that cannot be aligned must be explicitly marked UNALIGNABLE rather than silently mixed or reconstructed from unrelated clocks. Implementation instrumentation should record all events on one monotonic axis and never hard-code assumptions from captured timestamps (e.g., measured offsets must not be baked into the implementation). Confidence: 0.9
- Requires using actual event/field names from the artifact or repository when building timelines; names must not be invented. Confidence: 0.85
- Requires conclusions to be proven from evidence, not selected speculatively, and to be labeled CONFIRMED vs SUPPORTED INFERENCE vs UNKNOWN; claims about removable time must be grounded in serial critical-path effect. For authorized forensics batches, "needs more investigation," "likely," or "probably" is not an acceptable terminal state when another telemetry pass (redeploy → rerun → inspect) can answer the question — iterate instrumentation until direct evidence exists or it is proven unobtainable from the code/environment. Confidence: 0.85
- Wants numeric reconciliations to close exactly against the measured total with an explicitly reported residual (target residual <= 100 ms, ideally <= 25 ms), and any unexplained interval beyond a stated threshold to get an explicit row rather than being hidden inside residual/setup/overhead/handoff categories. Confidence: 0.8
- Prefers highly structured batch reports with mandated numbered sections and a fixed-format key-value final summary, and wants optimization rankings re-derived only from the reconciled evidence rather than carried over from earlier batches. Confidence: 0.8
- Uses a `--yolo` command to explicitly grant the agent full autonomy to keep working through a task without pausing to ask for permission or check in; once direction is given, the agent should proceed end-to-end. Reinforces this with terse continuation commands (e.g. "continue") rather than redirecting or micromanaging mid-task. Confidence: 0.75
- For implementation batches, code changes are authorized; guardrails are: current main worktree, no branch/worktree/commit unless explicitly instructed, and no remote/paid execution unless the batch prompt explicitly authorizes it (then unlimited IMPLEMENT → DEPLOY → COLD RUN 1 → COLD RUN 2 → ... cycles until every completion gate passes, without pausing to ask permission to retry). Prefers subagent-driven implementation/programming where available, falling back to direct work when subagents are unavailable. Confidence: 0.85
- When fixing a regression, must preserve already-working behavior explicitly named by the user (e.g., early-CLIP launch timing: manifest ~+36ms, lane ~+46ms, source read ~+48ms — "don't regress it"); a fix for one bottleneck must be verified to not disturb a proven optimization in the same batch, and the report must show the preserved metrics. Confidence: 0.7
- Treats user-observed platform measurements as authoritative and separate: a directly observed number (e.g., Modal-reported restore ≈ 4.08 s) must be preserved and reconciled, never replaced or relabeled by narrower internal metrics; when two clocks/boundaries cannot be reconciled, report BOTH totals rather than silently choosing one. Confidence: 0.85
- Minimizes paid/remote validation cost: exactly 1 deployment and 1 paid request per validation unless the user separately authorizes more; preserves hard single-run guards (e.g., --run-count 1) and never executes a prepared remote harness without authorization. Confidence: 0.85
- Requires added timing instrumentation to be optional/low-overhead and gated (e.g., env flag), using scoped CUDA events only when GPU timing is needed, and never adding global synchronization solely for timing. Any new diagnostic behavior must additionally be default-off unless it is deliberately retained harmless logging, fail-closed, and isolated from the normal production inference result. Confidence: 0.85
- For caching/reuse designs: requires exact-identity, fail-closed reuse — the identity key must contain every input capable of affecting correctness, and request-specific state (seed, prompt-dependent tensors, conditioning output, request IDs) must never be cached. Confidence: 0.75
- Classifies pre-graph/setup operations by whether their inputs actually vary across requests rather than by where the code currently executes them; request-specificity must be proven from input variance, not code location. Confidence: 0.7
- Prioritizes end-to-end critical-path metrics (time-to-first-sample, time-to-models-ready, time-to-response) over isolated stage/worker durations, and warns against summing overlapped work when projecting savings; the deciding metric is the WHOLE critical path and a win is never declared because one worker got faster while models-ready or sampling-start got later. Confidence: 0.85
- Prefers generic implementations over model-specific special-cases (e.g., "no Qwen-specific special case"; must be generic for ComfyUI text encoders; explicitly "Do NOT hard-code qwen_3_4b.safetensors"). Confidence: 0.75
- Requires optimization/speculative paths to be fail-closed and never weaken safety invariants: on any uncertainty (missing/stale manifest, identity mismatch, unexpected state, any error), fall back to the ordinary proven path; strict concurrency invariants (e.g., D15 — zero UNET GPU overlap with the CLIP critical phase) must be preserved even when promoting a fast path. Confidence: 0.9
- Demands performance claims be classified and evidence-grounded: improvements are labeled CONFIRMED vs HYPOTHESIS, never claimed as measured wins before remote validation, and never promise more than runtime evidence supports; misread/miscalculated prior measurements must be corrected in the historical report before optimizing further (never optimize a fictional interval). Confidence: 0.85
- When an optimization shows no measured win, disables it from the production default but keeps the implementation available behind an explicit experimental flag (never deletes the experiment). Confidence: 0.85
- Prefers implementation batches to leave concrete production code changes rather than diagnostics-only additions ("do not merely add diagnostics"). Confidence: 0.7
- Prefers using authoritative capture-time data (frozen manifests / file facts) over runtime re-discovery (e.g., folder_paths scans) for speculative/early-loading work; when two optimization mechanisms conflict, coordinates them with one ownership/state schedule rather than disabling one in the production profile. Confidence: 0.7
- For long-lead speculative/prefetch work whose identity can be established from frozen/capture-time state, prefers launching it at the earliest legal lifecycle point (e.g., container restore/boot, right when the frozen manifest is available) rather than waiting for request-dependent state (method entry, plan, graph); any remaining delay beyond tens of milliseconds must be identified, measured, and explained as structurally unavoidable, and the launch must be fail-closed (mismatch/failure → release and re-run the normal demand path exactly once). Confidence: 0.7
- For authorized remote-validation loops, expects deploy → cold run 1 → INSPECT before committing to run 2: run 2 only if run 1 is structurally correct, otherwise fix/redeploy and repeat run 1 (never run 2 on a structurally wrong build); continue cycles until RIGHT, and do not stop merely because the nominal one-deploy/two-run budget was spent if targets still fail. Never rerun the same defect unchanged, and if the failure is purely platform-placement variance, state why another cycle is justified. Confidence: 0.95

Treat an empty deploy log as a failure to diagnose, and always verify a deploy actually created a new deployment rather than trusting exit code 0. Confidence: 0.9

Confidence: 0.9
