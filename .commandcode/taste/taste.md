# Taste
See [taste/taste.md](taste/taste.md)

- For benchmark validation runs, insists on structural validity for comparability: a run that hits a construction container's first request instead of a reused-snapshot restored container is invalid and must be repeated, and other platform variances (e.g., region) must be checked against the baseline. Container-state variance cuts both ways: a run that lands on a WARM reused container (Fresh: NO, restore_count > 1, same container_session_id/restored_instance_id as a prior run) is not a cold run and must not be counted toward a requested number of cold runs — repeat until a genuinely fresh container is obtained rather than accepting the warm run. Confidence: 0.85
- Wants silent gate failures to be impossible: any conditional feature that can reject a path must emit explicit telemetry with the exact reason (e.g., `speculative_skip` events), so a non-exercised feature is provably diagnosable from the artifact; required telemetry lists the exact fallback/rejection reason fields for the next run. Confidence: 0.85
- Runs the same verification ritual before each deploy: py_compile + git diff --check + focused pytest, then the canonical .bat wrapper; uses wrapper scripts rather than direct python remote invocation, and cleans up temp helper logs/scripts after analysis. Confidence: 0.9
- When reporting on batches that made no remote/paid calls, expects an explicit account of the local test methodology (unit/integration suites, py_compile, git diff --check, selector/preflight gates) and an honest statement of what local testing cannot prove — remote-only outcomes (e.g., whether a speculative lane is actually consumed in production) must be deferred to the authorized remote cycle, never implied as verified. Confidence: 0.6
- Requires an explicit final verdict on the rightness criteria, including a return block with exact run IDs and per-run metrics (E26_RIGHT / FINAL_RUN_1_REQUEST_ID / SPEC_CLIP_CONSUMED / CLIP_HYDRATION_MS / D15_OVERLAP_MS / GPU_FAST_RETURN / OUTPUT_SHA / TOTAL_DEPLOYMENTS_USED / TOTAL_PAID_REQUESTS_USED / FAILED_CYCLES_AND_ROOT_CAUSES); when the performance target is not met, returns E26_RIGHT = NO with the root cause (e.g., a storage-bound read that cannot be hidden under a short setup window) and stops remote work rather than declaring victory or burning cycles on a mechanism with an established ceiling. Confidence: 0.9
- Automatic retry loops must halt when the failure cause is already known: if attempts fail for the same deterministic reason (e.g., no valid snapshot: `cpu_snapshot_models_present=0`, `snapshot_identity` empty), the harness must not keep retrying the identical attempt with cooldowns — stop, diagnose the deployment, and only re-run after the root cause is fixed; retries are only justified for transient/unknown causes. Confidence: 0.95
- Once a blocker's root cause is identified and a concrete recovery route exists (e.g., fresh app registration to force the construction lifecycle), must execute that route and iterate until the completion gates actually close — stopping again to re-report the same known blocker as terminal, or finishing with "PARTIALLY COMPLETE / pending valid run / environment blocker / needs implementation batch to measure", is not acceptable. Confidence: 0.85
- Reacts immediately when a command "never returns": a long-running/background shell that hangs (e.g., a piped wrapper that swallows output and never exits cleanly) is flagged by the user as a problem. Avoid launching commands in a way that can hang indefinitely — prefer bounded foreground execution, verify completion via state artifacts rather than the shell's exit, and kill stuck tasks promptly instead of leaving them running. Confidence: 0.8
- When a correction identifies a recurring core failure, demands that remote validation stop and the architecture be fixed first: first trace the existing evidence (persisted run artifacts, not new runs), do not spend more runs confirming a known failure — diagnose from captured evidence, fix the implementation (e.g., the loader regression and the accidental serialization blocking another model's forward) locally, then redeploy and run the next cold validation gate. "No additional blind runs" before the evidence trace is complete. Confidence: 0.9
